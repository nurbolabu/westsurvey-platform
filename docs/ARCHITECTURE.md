# Как устроена платформа WestSurvey

Платформа показывает ход строительства автодороги Асан – Азгир – Балкудык в Атырауской области: карту трассы с пикетами, готовность каждого слоя конструкции, подрядчиков, геодезию и лабораторию. Этот документ описывает, какие данные нужны, откуда они берутся, кто их вносит и как устроен бэкенд.

## 1. Общая схема

```
 Телефон / ноутбук на объекте            Офис WestSurvey, технадзор, заказчик
            │                                         │
            ▼                                         ▼
 ┌────────────────────────── Веб-приложение (этот репозиторий) ─────────────────────────┐
 │  Карта (MapLibre + Mapbox)   Линейный график   Окно пикета   Ввод данных   Журнал    │
 └──────────────────────────────────────────┬───────────────────────────────────────────┘
                                            │ HTTPS, JWT пользователя
                                            ▼
 ┌──────────────────────────────── Supabase ────────────────────────────────────────────┐
 │  Auth (вход, роли)   PostgreSQL + PostGIS (данные, геометрия)   Storage (файлы, фото)│
 │  RLS: каждый видит и вносит только то, что положено его роли                         │
 └──────────────────────────────────────────────────────────────────────────────────────┘
                                            │
                                            ▼
                     Mapbox: спутниковые снимки, рельеф, ортофото с дрона
```

Почему так:
- **Supabase** даёт в одном месте базу PostgreSQL с PostGIS, вход пользователей, хранилище файлов и права доступа на уровне строк. Отдельный сервер писать не нужно. Бесплатного тарифа хватит на пилот, рабочий тариф около 25 $ в месяц.
- **PostGIS** хранит ось трассы, пикеты и отрезки как геометрию и сам считает пикеты по оси.
- **Фронтенд статический**: размещается на GitHub Pages, Vercel или любом хостинге.

Сейчас в прототипе вместо Supabase работает локальное хранилище браузера (`entries.js`). Интерфейс `Store` тот же, поэтому при подключении базы меняется только этот файл.

## 2. Данные для карты

| Что | Откуда | Формат для загрузки | Обязательно |
|---|---|---|---|
| Ось трассы | AutoCAD / Civil 3D, геодезия | KML или GeoJSON, линия (LineString), WGS84 | да |
| Пикетаж | считается по оси автоматически, шаг 100 м | точки «ПК N» в KML как проверка | да |
| Начало трассы (ПК 0) | проект | первая точка оси | да |
| Участки подрядчиков | договоры | ПК от – ПК до | да |
| Граница полосы отвода | проект | KML/GeoJSON, полигон | желательно |
| Искусственные сооружения: трубы, мосты | проект | точки или линии | желательно |
| Карьеры, АБЗ, базы | проект | точки | по желанию |
| Ортофотоплан с дрона | съёмка раз в 2–4 недели | GeoTIFF → тайлсет Mapbox | желательно |
| Цифровая модель рельефа | съёмка или проект | GeoTIFF | по желанию |

### Как получить KML из AutoCAD

1. Определите систему координат чертежа. В Казахстане это часто местная система (МСК) или СК-42/СК-63. Без этого трасса окажется не на своём месте.
2. Civil 3D: команда `MAPEXPORT` → формат KML или SHP, слой оси трассы.
   Обычный AutoCAD: сохранить ось в DXF.
3. Откройте файл в QGIS, задайте исходную систему координат и экспортируйте в KML или GeoJSON с системой **EPSG:4326 (WGS84)**.
   То же из командной строки:
   ```
   ogr2ogr -f KML -s_srs "<proj-строка МСК>" -t_srs EPSG:4326 route.kml axis.dxf
   ```
4. Загрузите файл в разделе **Ввод данных → Трасса и проект**. Платформа покажет длину оси и число пикетов до применения.

### Как подключить Mapbox

1. Зарегистрируйтесь на mapbox.com, создайте **публичный токен** (начинается с `pk.`).
2. В настройках токена укажите **URL restrictions**: адрес сайта платформы. Тогда токен бесполезен на чужих сайтах.
3. Вставьте токен в `config.js` (`mapboxToken`) или в разделе **Ввод данных → Трасса и проект**.
4. Бесплатный тариф Mapbox: 50 000 загрузок карты в месяц для веб-карт и 200 000 запросов к тайлам. Для внутренней платформы с десятками пользователей этого с запасом хватает.
5. Ортофото с дрона: Mapbox Studio → Tilesets → загрузить GeoTIFF. Полученный идентификатор тайлсета добавляется в карту как растровый слой.

Рельеф берётся из открытых AWS Terrain Tiles: Mapbox Terrain DEM доступен только библиотеке Mapbox GL JS. Без токена снимки берутся из Esri World Imagery. Для пилота этого достаточно, для рабочей версии лучше Mapbox: снимки свежее, есть договор и поддержка.

## 3. Кто и что вносит

| Роль | Что вносит | Где | Что видит |
|---|---|---|---|
| Прораб подрядчика | ежедневный отчёт: участок ПК, слой, объём за смену, техника, люди, фото | Ввод данных → Отчёт о работах, с телефона | весь объект, вносит только на своём участке |
| Геодезист WestSurvey | акты разбивки, исполнительные съёмки (DWG/PDF), дата следующей съёмки | Ввод данных → Геодезия | весь объект |
| Лаборатория | протоколы: уплотнение, влажность, щебень; соответствует / нет | Ввод данных → Лаборатория | весь объект |
| Технадзор | подтверждает или отклоняет записи, пишет замечания | Журнал и подтверждение | весь объект |
| Заказчик | смотрит, при необходимости подтверждает | всё | весь объект |
| Администратор | ось трассы, проектные объёмы (CSV), подрядчики, пользователи | Трасса и проект | всё |

**Главное правило:** запись попадает в факт только после подтверждения технадзором. До этого она видна в журнале со статусом «Ожидает подтверждения». Так в отчётах заказчику нет неподтверждённых объёмов.

### Как распределяется объём

Прораб пишет «ПК 100 – 105, слой I, 2 500 м³». Объём делится между пикетами 100–104 пропорционально тому, сколько на каждом осталось по проекту. Так один отчёт закрывает участок целиком, и не нужно вносить каждый пикет отдельно. В базе это делает триггер `distribute_report`.

### Проектные объёмы

Загружаются один раз из ведомости объёмов: CSV с колонками `pk;layer;design_volume` (шаблон в `templates/design_volumes_template.csv`). Коды слоёв: `base, s1, s2, s3, s4, s5, gravel, bitumen, recycler`.

## 4. База данных

Полная схема: `supabase/migrations/0001_init.sql`.

Основные таблицы:
- `projects`, `contractors`, `contracts`, `profiles` (пользователь и роль), `layers` (слои и плановые даты);
- `route` (ось трассы, геометрия), `pickets` (точка и отрезок каждого пикета), `map_features` (отвод, трубы, мосты, карьеры);
- `design_volumes` (проект по пикету и слою);
- `work_reports` → `work_volumes` (отчёты и их распределение по пикетам), `surveys`, `lab_tests`, `photos`.

Готовые представления для экранов:
- `v_layer_progress`: готовность каждого слоя на каждом пикете;
- `v_picket_status`: готовность пикета, последняя и следующая съёмка, геометрия;
- `picket_geojson(project_id)`: вся трасса для карты одним запросом.

`rebuild_pickets(project_id)` пересчитывает пикеты после загрузки новой оси.

Права (RLS): читать могут все вошедшие участники проекта; вносить отчёты может только подрядчик на своём участке; подтверждать могут технадзор, заказчик и администратор; ось и проектные объёмы меняет только администратор.

Файлы (договоры, DWG, PDF, фото) лежат в Supabase Storage в папках `contracts/`, `surveys/`, `lab/`, `photos/`; в таблицах хранится только путь.

## 5. Что сделано в прототипе и что дальше

Сделано:
- карта на весь экран: спутник, рельеф, 3D, пикеты по статусам, участки подрядчиков, клик по пикету;
- импорт оси из KML/GeoJSON с проверкой координат;
- ввод отчётов, съёмок, протоколов, проектных объёмов (CSV) с подтверждением технадзором;
- после подтверждения сразу обновляются карта, линейный график и окно пикета;
- схема базы, роли и права доступа.

Следующие шаги:
1. Создать проект Supabase, применить миграцию, завести пользователей и роли.
2. Заменить `entries.js` на работу с Supabase (тот же интерфейс `Store`).
3. Загрузить настоящую ось трассы и ведомость проектных объёмов.
4. Подключить токен Mapbox и ортофото с дрона.
5. Загрузку файлов и фото перевести в Supabase Storage.
6. Уведомления технадзору о новых записях (почта или Telegram).
